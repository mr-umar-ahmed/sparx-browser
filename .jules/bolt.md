## 2024-05-18 - Keystroke State Causing Full Tree Re-renders
**Learning:** In the Sparx Electron + React architecture, complex high-level components like `App.tsx` were holding highly volatile state (like `currentMessage` for the chat input and `inputUrl` for the URL bar). Because of this architecture, typing a single character was triggering a full re-render of massive child components like the `ScrollMorphHero` (which handles complex 3D math and many `FlipCard` children) and the entire chat history (which uses expensive `ReactMarkdown` and `SyntaxHighlighter` modules).
**Action:** Always extract volatile state out of the root components when possible. When dealing with heavy child components or lists that map over complex elements, extract them into separate component files and aggressively wrap them in `React.memo()`. Ensure their props are stable (e.g., using `useCallback` for functions and `useMemo` for derived objects) to protect them from unnecessary renders caused by distant sibling state changes.
